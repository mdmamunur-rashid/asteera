Pathao API Integration Guide

This document explains the setup and functionality of the Pathao Courier integration with your Google Sheets, primarily driven by the PathaoIntegration.gs script.

1. Overall Purpose of PathaoIntegration.gs:

This script is designed to automate interaction with the Pathao Courier Merchant API. Its main functionalities include:

  • Authentication: Securely obtaining and managing access tokens required by Pathao.
  • Location Data Management: Fetching and caching lists of Pathao-supported cities (districts) and zones (thanas) with their IDs.
  • Order Creation: Sending new delivery orders to Pathao based on processed data from your Google Sheet.
  • User Interface: Providing a user-friendly way to configure API credentials and refresh location data directly from the Google Sheet.

2. Required Credentials and How They Are Managed:

The Pathao API uses OAuth 2.0, which requires several pieces of information for authentication and to identify your merchant account. These are now managed securely using Google Apps Script's PropertiesService and configured through a dedicated sidebar UI.

Credentials Needed:

  • Client ID: Your unique identifier for your application with Pathao.
  • Client Secret: A confidential key used to authenticate your application.
  • Username (Email): The email address associated with your Pathao merchant account.
  • Password: The password for your Pathao merchant account.
  • Pathao API Base URL: The base endpoint for Pathao API requests (e.g., https://api-hermes.pathao.com for production or https://courier-api-sandbox.pathao.com for testing).
  • Pathao Store ID: A specific ID for one of your registered stores with Pathao. This ID tells Pathao where the pickup location for an order is.

How to Configure These:

You no longer need to edit the script code directly for these. Instead, from your Google Sheet:

  1. Go to Pathao Orders (custom menu) -> Configure Pathao API.
  2. A sidebar will open where you can input these values.
  3. Click "Save Configuration" to securely store them using PropertiesService, which keeps them private to your script and Google account.

3. Authentication Flow (getAccessToken and _getAuthTokenForPathaoIntegration):

The Pathao API's OAuth 2.0 authentication is handled automatically by the script:

  • getAccessToken(config) Function:
    • Token Caching for Efficiency: It checks PropertiesService for an existing, valid access_token. If found and not expired (with a 5-minute safety buffer), it returns the cached token.
    • Automated Token Refresh: If the token is expired but a refresh_token is available, it automatically uses the refresh_token to request a new access_token from Pathao's /issue-token endpoint.
    • Initial Authentication: If no valid tokens are found, it performs the initial authentication using your configured username and password to obtain both an access_token and a refresh_token.
    • Secure Storage: All new tokens and their expiry times are securely saved into PropertiesService.
  • _getAuthTokenForPathaoIntegration() Helper:
    • An internal helper used by functions like fetchPathaoLocations() to securely retrieve an access token using the stored configuration.
  • Forced Re-authentication upon Credential Changes:
    • If you modify any API credentials (Client ID, Secret, Username, Password, or Base URL) in the sidebar and save, the script automatically deletes existing tokens from PropertiesService. This forces a fresh authentication with the new credentials the next time an API call is made, preventing potential errors.

4. Location Data Management (fetchPathaoLocations, getOrFetchPathaoLocations):

To accurately identify District and Thana IDs, the script needs a comprehensive list of Pathao's recognized locations.

  • fetchPathaoLocations():
    • This function makes API calls to Pathao (using your access token) to get the complete lists of:
      • Cities (/aladdin/api/v1/city-list) - These are treated as Districts.
      • Zones (/aladdin/api/v1/cities/{city_id}/zone-list for each city) - These are treated as Thanas.
    • API Rate Limiting & Delay: A 300ms delay is now included between fetching zones for each city to avoid hitting Pathao API rate limits.
    • Smart Caching: The fetched cities and zones (with their ids and names) are stored in PropertiesService, along with a timestamp. This cache is valid for 24 hours to reduce API calls.
    • Visual Cache Representation: The fetched location data is also written to a sheet named "pathao addresses". This sheet serves as a readable copy of the cached data and is populated each time locations are refreshed.
    • Manual Refresh: You can trigger a manual refresh of this data via Pathao Orders -> Refresh Pathao Locations in the sheet's menu or by clicking the button in the configuration sidebar.
  • getOrFetchPathaoLocations():
    • This is the function used by the script to get location data. It first checks for valid cached data. If the cache is old or missing, it automatically calls fetchPathaoLocations() to update the cache before returning the data.
    • Dropdown Source: All dropdown options for Districts and Thanas, as well as the logic for fuzzy matching, are sourced directly from this cached memory for optimal performance, not from the "pathao addresses" sheet.

5. Order Creation (createPathaoOrder):

This function sends your processed order details to Pathao.

  • It uses the access_token to authenticate the request to Pathao's /aladdin/api/v1/orders endpoint.
  • The orderPayload contains all delivery details, including store_id, recipient information, product details, and the amount_to_collect.
  • Crucially, the recipient_city and recipient_zone parameters (which use the cityId and zoneId from the address extraction) are part of this payload, ensuring the order is routed correctly.
  • Prioritizing Existing IDs: When an order is placed, the script first attempts to use any existing values in the District ID and Thana ID columns directly. Fuzzy matching and ID lookup only occur if these ID columns are empty.

6. Webhook Integration (PathaoWebhook.gs):

This is a separate script designed to receive status updates from Pathao regarding your orders.

  • You deploy it as a Google Apps Script Web App, which gives it a unique URL.
  • This URL and a WEBHOOK_SECRET are provided to Pathao through their merchant panel.
  • When Pathao sends an update (e.g., "Order Delivered"), PathaoWebhook.gs verifies the secret and then uses the consignment_id (tracking number) from the payload to find the corresponding row in your sheet and update its "Order Status".

7. Address Location Processing and Dynamic Dropdowns (in PathaoIntegration.gs and onEdit trigger):

The script intelligently processes address information to identify Pathao locations and provides an interactive user experience in your main order sheet.

  • Automated ID Population (`findAndSetLocationIds`):
    • When the CUSTOMER ADDRESS column is edited, or when "Find & Fill Missing Locations" is clicked, this function attempts to extract District and Thana information.
    • Fuzzy Matching & Accuracy:
      • The system uses Levenshtein distance for fuzzy matching to account for minor misspellings.
      • It employs a two-pass approach:
        1. Primary Match: Seeks the best match with a similarity score of 70% (0.7) or higher.
        2. Secondary Fallback: If no primary match is found, it accepts the single best match with the highest overall similarity score (even if below 70%), aiming for the "nearest matching" location.
      • Prioritizing End of Address: When searching for matches, words appearing later in the address string are prioritized.
      • Visual Cues: If a fuzzy match (primary or secondary) is made, the District and Thana cells are formatted in red to indicate a non-exact match.
      • Clearing on No Match: If an address edit results in no matching District or Thana, any previously filled data and formatting in the District, Thana, District ID, and Thana ID cells are explicitly cleared, and the Thana dropdown is reset.
  • Interactive Dynamic Dropdowns (`setupLocationDropdowns` and `onEdit`):
    • Initial Setup: The Pathao Orders -> Setup Location Dropdowns menu item (or function) configures the data validation. It sets up a dropdown for the District column listing all available districts and a placeholder dropdown for the Thana column. This setup is applied to a practical range of rows (e.g., 500 rows) even on empty sheets.
    • Dynamic Thana Options: When a District is selected from its dropdown:
      • The Thana dropdown in the same row is automatically updated to show only Thanas belonging to the selected District.
      • The corresponding District ID is auto-populated.
      • The existing Thana selection and Thana ID are cleared.
    • Thana ID Auto-population: When a Thana is selected from its (now dynamic) dropdown, the corresponding Thana ID is automatically populated.
    • Automatic Thana Dropdown Update with Address Edits: If District and Thana are automatically identified and filled based on an address edit (via `findAndSetLocationIds`), the Thana dropdown for that row is also dynamically updated with the correct options for the identified District.

Steps to Get Started:

  1. Open Google Apps Script Project: Go to your Google Sheet (the one with ID 1Ad1xyjH96HKUMt5BijlBgpqKuzcd8JZf0NBdm0OhA7A) and open Extensions > Apps Script.
  2. Ensure Scripts are Up-to-Date: Make sure code.js, PathaoIntegration.gs, PathaoWebhook.gs, and PathaoConfig.html in your Apps Script project contain the latest code provided to you.
  3. Deploy PathaoWebhook.gs as a Web App: As instructed previously, deploy this script as a Web App and configure its URL and WEBHOOK_SECRET in your Pathao Merchant Panel.
  4. Configure Pathao API Credentials:
    1. In your Google Sheet, go to Pathao Orders -> Configure Pathao API.
    2. Fill in all the required fields (Client ID, Client Secret, Username, Password, Base URL, Pathao Store ID).
    3. Important: Use your Pathao merchant account credentials. For Base URL, choose https://api-hermes.pathao.com for production.
    4. Click "Save Configuration".
  5. Authorize Script: The first time you run these functions (especially after saving config or refreshing locations), Google will ask for authorization. Follow the prompts to grant necessary permissions.
  6. Refresh Pathao Locations: Go to Pathao Orders -> Refresh Pathao Locations (or click the button in the configuration sidebar). This is vital to populate the internal lists of cities and zones needed for address parsing and for the "pathao addresses" sheet.
  7. Setup Location Dropdowns: Go to Pathao Orders -> Setup Location Dropdowns. This will configure the interactive District and Thana dropdowns in your main order sheet. This step needs to be done once after setting up the script, or if you create new sheets/columns and want the dropdowns applied.
  8. Start Processing Orders: Now, when new form submissions come in or you edit address cells, the script should automatically extract and populate all the necessary data, including District, Thana, and their IDs, ready for Pathao order creation. You can also manually select locations using the new dropdowns.

This comprehensive setup ensures a robust and automated integration with the Pathao Courier Merchant API.
